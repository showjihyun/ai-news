## 장애 발생: 금요일 오후부터 로그인 차단

앤스로픽의 클로드 AI 서비스(claude.ai)에서 금요일 오후 로그인 오류가 발생했다. 해커뉴스 사용자들에 따르면 접속 시 클라우드플레어(Cloudflare) 차단 페이지가 뜨거나 인증 단계에서 멈췄다. 앤스로픽 공식 상태 페이지에서도 사고 조사 중임을 알렸다.

장애 범위는 웹 채팅에 그치지 않았다. 해커뉴스 댓글에 정리된 영향도는 claude.ai 주요 장애, Claude Console 부분 장애, Claude Code 부분 장애, Claude Cowork 성능 저하, Claude API는 정상이다.

한 사용자는 "와이파이를 바꾸니 다시 됐다"며 네트워크 경로에 따라 증상이 갈린다고 전했다. 또 다른 사용자는 "무료 사용량 리셋 버그 때처럼 너그럽게 처리해 주길 바란다"는 반응을 보였다.

## 쉽게 풀어보면

앤스로픽이 운영하는 클로드 AI 웹사이트와 개발자 도구 여러 곳에서 **로그인 자체가 안 되는 상황**이 벌어졌다. 식당 문은 열려 있는데 출입문 열쇠가 안 돌아가는 격이다. 다행히 **API(프로그램 연동 창구)는 정상**이라, 직접 코드로 클로드를 호출하는 개발자나 연동 서비스는 영향이 없었다.

장애는 금요일 오후 시작됐고, "잠시 풀렸다가 다시 막혔다"는 제보가 이어졌다. 원인은 아직 공개되지 않았다. 앤스로픽은 상태 페이지에서 조사 중이라고만 밝혔다.

한국에서 클로드 웹을 쓰던 사람이라면 **오늘 접속이 안 된 게 내 기기 탓이 아니다**는 점만 알아두면 된다. API를 쓰는 서비스(예: 커서, 클라인 등)는 평소처럼 돌아갔을 가능성이 크다.

## 나에게 미치는 영향

**일반 사용자(웹 채팅만 쓰는 경우)**
claude.ai 접속이 안 되면 기다리는 수밖에 없다. 브라우저 캐시 삭제, 다른 네트워크(모바일 데이터 등) 시도가 일시적으로 통할 수 있다. 급한 작업은 **챗GPT(chatgpt.com)**나 **제미나이(gemini.google.com)**로 옮겨서 진행하자.

**개발자·헤비 유저(Claude Code, Console 쓰는 경우)**
**API 키는 살아 있다**. 터미널에서 `claude` 명령어나 직접 HTTP 요청을 보내면 정상 작동한다. 클로드 코드 CLI가 인증 에러를 내면 `claude auth login`을 다시 실행해 보자. 콘솔 웹이 막혀도 토큰 발급은 API 경로로 우회될 수 있다. 커서(Cursor), 클라인(Cline), 아비드(Aider) 같은 에디터 연동 도구는 API를 쓰므로 **장애 영향 없이 계속 쓸 수 있다**.

## 남은 쟁점: 원인 미공개, 보상 논의는 아직

앤스로픽은 장애 원인을 **공개하지 않았다**. 클라우드플레어 차단 화면이 떴다는 제보가 있지만, CDN 설정 오류인지 인증 서버 다운인지 알 수 없다. 과거 무료 사용량 측정 버그 때는 사용량을 리셋해 준 전례가 있으나, 이번 건에 대한 보상 언급은 없다.

웹 프론트엔드와 API 게이트웨이가 분리돼 운영된다는 방증으로 읽힌다. **이 대목이 걸린다.** 웹과 API가 따로 놀면 장애 격리는 되지만, 사용자 입장에선 어디까지 믿어야 할지 모호해진다. 본지가 확인한 자료만으로는 원인 규명까지 갈 수 없다.

## 한국 사용자 체크리스트

- claude.ai 안 되면 **모바일 데이터로 한 번 시도** — 네트워크 경로에 따라 뚫릴 수 있다
- API 키 있는 개발자는 **터미널·에디터 연동 도구부터 확인** — 웹 장애와 무관하게 작동할 확률 높다
- 급한 작업은 **챗GPT·제미나이 병행** — 둘 다 바로 쓸 수 있다
- 상태 페이지 **북마크 해두기** — 다음 장애 때 가장 빠른 공식 소스다

장애가 완전히 해소됐다는 공식 발표는 아직 없다. 쓰던 도구가 안 되면 다른 창구로 바로 갈아타는 수밖에.
