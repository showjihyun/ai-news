깃허브에 '라마-모드칩(llama-modchip)'이라는 프로젝트가 올라왔다. 64GB 시스템 메모리만으로 2840억 파라미터(284B) 규모의 딥시크-V4-플래시 모델을 GPU 없이 돌릴 수 있게 한 도구다. 개발자는 시놉테이트(synchopate)라는 닉네임을 쓴다. 해커뉴스에서 116점, 댓글 36개를 받으며 화제가 됐다.

핵심은 독자 양자화 방식 '프랙탈-64(Fractal-64)'다. 기존 GGUF 포맷이 지원하지 않는 커스텀 텐서 타입(GGML_TYPE_Q2_0 = 40)을 쓴다. 블록 단위 64비트 BF16 스케일에 그레이 코드를 결합해 2비트 수준으로 압축하면서도 품질 저하를 최소화했다. 이 텐서는 일반 라마.cpp, 올라마, LM 스튜디오에서 열리지 않는다. 전용 패치 바이너리나 제공하는 단일 실행 파일로만 구동된다.

지원 모델은 두 가지다. 30B 네모트론-3.5-30B-A3B는 14.35GiB로 16~32GB 램에서 초당 25~60.4토큰 나온다. 284B 딥시크-V4-플래시는 56.56GiB로 64GB 램에 들어가며 초당 9.1~14.7토큰을 낸다. 둘 다 256K 컨텍스트를 지원한다. MoE(전문가 혼합) 구조라 활성 파라미터는 131.7억 수준에 불과하다.

리눅스·맥은 `git clone` 후 `./modchip chat` 한 명령으로 끝난다. 윈도우는 `windows/AVVIA_MODCHIP.bat` 더블클릭이면 CPU 코어·램·GPU VRAM을 자동 감지해 최적 분할(`--n-cpu-moe`)을 계산하고 웹 채팅 UI를 연다. 사전 컴파일된 바이너리는 허깅페이스 레포와 깃허브 릴리스 v2.4.0에 들어 있다.

벤치마크 스크립트(`./modchip bench` 또는 `BENCHMARK_PC.bat`)로 점수를 내고 깃허브 이슈로 제출하면 공식 리더보드에 오른다. 문서에는 젠5, 스레드리퍼, 벌칸, 쿠다, 메탈, ARM64별 최적화 플래그와 수학적 증명이 실려 있다.

## 쉽게 풀어보면

이 도구는 **거대 언어 모델을 일반 사무용 PC 메모리에 욱여넣는 압축 기술**이다. 비유하자면 284권짜리 백과사전 세트를 64GB짜리 책장 한 칸에 꽂을 수 있게 압축해 둔 셈이다. 원래라면 이 백과사전은 수십 기가바이트짜리 비디오 메모리(HBM)가 달린 엔비디아 GPU 서버가 있어야 읽을 수 있었다.

비결은 '전문가 혼합(MoE)' 구조다. 284B 모델 전체를 한꺼번에 쓰는 게 아니라, 질문 종류에 따라 13B 정도만 골라 쓴다. 여기에 2비트 양자화로 무게를 더 줄였다. 단, 압축 방식이 표준이 아니라 전용 리더기(패치된 바이너리)가 있어야 펼칠 수 있다.

속도는 초당 10토큰 안팎. 초당 3~4단어 정도 읽는 속도라 대화용으로는 약간 느리다. 하지만 코드 리뷰, 문서 요약, 에이전트 여러 개를 동시에 띄우는 배치 작업에는 충분히 쓸 만하다. 해커뉴스 댓글에서도 "여러 에이전트를 병렬로 돌릴 때 처리량이 확 오른다"는 경험담이 있었다.

## 나에게 미치는 영향

64GB 램이 달린 리눅스·맥·윈도우 머신이 있다면 **오늘 바로 테스트해 볼 수 있다**. 단계는 다음과 같다.

**리눅스·맥**
```bash
git clone https://github.com/synchopate/llama-modchip.git
cd llama-modchip
./modchip chat
```
자동으로 모델을 내려받고 채팅창이 뜬다. 30B 네모트론을 먼저 써보고 싶다면 위 명령만으로 충분하다. 284B 딥시크를 쓰려면 램 64GB가 반드시 필요하다.

**윈도우 10/11**
`windows` 폴더 안 `AVVIA_MODCHIP.bat`를 더블클릭한다. 파이썬·쿠다·불칸 바이너리까지 자동 설치되며 브라우저에 `http://127.0.0.1:8080` 채팅창이 열린다.

**확인할 것**
- `./modchip bench`(윈도우: `BENCHMARK_PC.bat`)로 내 CPU·램 조합에서 초당 토큰 수를 찍어 보자. 리더보드에 제출하면 내 순위도 보인다.
- 284B 모델 로딩 시 `unknown tensor type 40` 에러가 나면 일반 라마.cpp가 아닌 **전용 바이너리**를 쓰고 있는지 확인하라. 허깅페이스 레포(`Synchopate/DeepSeek-V4-Flash-0731-Fractal-64GB-CPU-GGUF`)에 들어 있는 `llama-server-modchip-linux-x86_64`를 써야 한다.

**막히는 지점 해결**
- 램 32GB 이하: 284B는 안 된다. 30B 네모트론만 가능하다.
- 맥 M시리즈: `apple-silicon/` 폴더 안 가이드를 따라 메탈 백엔드로 빌드해야 한다.
- 속도 불만: `-t`(스레드 수)를 물리 코어 수로 맞춰라. 하이퍼스레딩 켜두면 오히려 느려질 수 있다.

## 커뮤니티 반응과 남은 의문

해커뉴스 댓글 36개 중 눈에 띄는 반응을 추렸다.

- "문서가 거의 LLM 요약 없이는 못 읽을 수준" — README·최적화 가이드가 지나치게 기술적이란 지적.
- "딥시크 V4 플래시 2비트 양자화는 쓸 만하던데, 다른 모델은 2비트에서 품질이 무너지더라" — 이 모델 특유의 내성이 있다는 경험담.
- "로컬 모델은 병렬 에이전트 돌릴 때 빛난다. 개별 속도는 느려도 전체 처리량은 GPU 클러스터에 육박한다" — KV 캐시 부담이 적은 MoE 특성 덕분으로 보인다.
- "큐원(Qwen)도 이 체계로 포팅됐으면" — 다른 모델 지원 요청.

공개된 프리프린트 PDF와 최적화 문서엔 수학적 증명과 연산자 단위 레이턴시 표가 있지만, **독립 재현 벤치마크는 아직 없다**. 개발자가 직접 올린 수치(9.1~14.7 tok/s, 25~60.4 tok/s)만 있다. 또 엔터프라이즈·하드웨어 스폰서십을 공개 모집 중이라 상용화 방향성이 바뀔 수도 있다.

## 인텔 D시리즈와 다른 점

본지가 26일 전 다룬 [인텔 D시리즈 GPU 공개, 480GB 메모리로 거대 모델 겨냥](/posts/2026-10-13-인텔-d시리즈-gpu-공개-480gb-메모리로-거대-모델-겨냥/) 기사는 **하드웨어로 메모리 벽을 넘으려는 시도**였다. 라마-모드칩은 **소프트웨어 압축으로 기존 램 안에서 해결**하려는 접근이다. 전자는 480GB HBM을 단 전용 카드가 필요하고, 후자는 이미 가진 64GB DDR5로 당장에 쓸 수 있다. 용도도 다르다. 인텔은 학습·파인튜닝까지 노리지만, 이 도구는 추론 전용이다.

## 확인 안 된 것들

- 윈도우에서 하이브리드 GPU+CPU 분할(`--n-cpu-moe`)이 실제로 최적인지 제3자 검증 없음.
- 256K 컨텍스트 전 구간에서 품질이 유지되는지 롱컨텍스트 벤치마크(니들인헤이스택 등) 결과 없음.
- 상용 지원·SLA·보안 감사 여부. 현재는 개인·연구 용도 배포판이다.

관심 있다면 깃허브 레포 `docs/HARDWARE_OPTIMIZATIONS.md`부터 읽어보라. 내 CPU가 지원 목록에 있는지, 어떤 플래그를 켜야 하는지 5분이면 확인된다.
