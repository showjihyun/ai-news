법률 AI 스타트업 하비(Harvey)가 5억 달러(약 6800억 원) 투자를 유치했다는 소식이 나온 지 얼마 안 돼, 깃허브에 그와 유사한 기능을 무료로 쓸 수 있는 도구가 올라왔다. 개발자 토마스 우니즈(Thomas Unise)가 만든 '케이스사이트(CaseCite)'다. 하비가 기업용 SaaS로 팔고 있는 문서 분석·판례 검색·메모 초안 작성 등을, 직접 설치해 쓰는 오픈소스 형태로 공개했다.

## 핵심 차이는 데이터가 머무는 위치다

케이스사이트는 문서·검색 인덱스·채팅 기록을 사용자 서버에만 저장한다. AI 기능은 사용자가 직접 발급받은 API 키(BYOK)를 통해 오픈AI 등 외부 모델로 질의만 보낸다. 유지보수 측으로는 어떤 원격 측정(텔레메트리)도 심지 않았다. 아파치 2.0 라이선스라 상용 이용·수정·재배포 모두 가능하다.

## 하비와 무엇이 다른가

하비는 전직 변호사들이 창업해 법률 워크플로를 깊이 이해한다는 평가를 받는다. 로펌이 비싸게 쓰는 이유도 '기능'보다 '책임 소재'와 '신뢰'에 가깝다. 해커뉴스 댓글에서도 "로펌은 리스크 관리를 위해 검증된 벤더를 산다"는 지적이 나왔다. 케이스사이트는 그 신뢰 계층이 없다. 코드와 배포 책임이 전적으로 사용자한테 있다.

기능 면에선 여덟 가지 도구를 한 로그인으로 쓴다. 문서 업로드, 판례·판사 검색, 메모·초안 작성, 레드라인(수정 비교) 검토, 실무 프로필 기반 맥락 유지 등이 포함된다. 실무 프로필은 사용자가 자신의 전문 분야를 적으면 그에 맞춘 맥락을 자동 생성해 주고, 이후 모든 분석에 끼워 넣는다. 단, 모든 AI 답변에는 "원문과 현행 법령으로 검증하라"는 경고 문구가 붙는다. 변호사 판단을 대체하지 않는다는 뜻이다.

## 직접 돌리려면 준비할 것들

설치 문서를 보면 도커·도커 컴포즈·오픈SSL이 필수다. 오픈AI API 키 하나만 있으면 바로 시작할 수 있지만, 문서 텍스트가 임베딩 단계에서 오픈AI로 간다. 완전히 내부망에서만 돌리려면 채팅용·임베딩용 모델 둘 다 자체 서버(OPENAI_BASE_URL, EMBEDDING_BASE_URL)에 띄워야 한다. GPU 서버와 모델 운영 노하우가 별도로 든다.

암호화도 조건부다. BYOK 키와 업로드 문서는 애플리케이션 계층에서 AES-256-GCM으로 암호화하지만, 벡터 청크·채팅 기록·분석 결과는 평문으로 DB(포스트그레스)와 레디스에 남는다. 풀 디스크 암호화는 호스트 서버 관리자가 직접 해야 한다. `.env` 파일에 `DISK_ENCRYPTION_ACKNOWLEDGED=true`를 적지 않으면 부팅조차 안 된다.

## 커뮤니티 반응: "바이브 코딩 냄새 난다"

해커뉴스에선 "클릭하자마자 바이브 코딩한 티가 난다"는 냉소적 반응이 나왔다. AI가 짜준 코드를 검토 없이 올린 것 아니냐는 의심이다. 반면 "바이브 코딩이어도 동작하면 그만 아니냐"는 반론도 있었다. 실제 코드 품질·보안 검증은 아직 커뮤니티에서 진행 중이다. 제작자 본인도 "상용 지원과 프라이빗 설치는 별도 문의하라"며 유지보수 부담을 일부 인정했다.

## 쉽게 풀어보면

케이스사이트는 로펌이나 기업 법무팀이 쓰는 '법률 비서 AI'를 직접 설치해 쓰는 버전이다. 하비 같은 유료 서비스는 월 구독료를 내면 클라우드에서 바로 쓰지만, 케이스사이트는 서버를 내가 준비하고, 모델도 내가 골라 붙이고, 보안 설정도 내가 책임진다.

비유하자면 이렇다. 하비는 **전문 비서 파견 업체**다. 검증된 비서를 보내주고, 실수하면 업체가 책임진다. 비싸지만 안심이다. 케이스사이트는 **비서 매뉴얼과 도구 상자를 무료로 주는 것**이다. 비서를 내가 뽑고(모델 선택), 사무실(서버)도 내가 구하고, 실수하면 내가 감당한다. 공짜지만 품이 많이 든다.

한국 로펌이나 법무팀이 당장 쓰려면 다음 네 가지가 선행돼야 한다:

- 도커 운영 가능한 인프라팀
- GPU 서버 혹은 클라우드 크레딧
- 오픈AI 혹은 대체 모델 API 키
- 개인정보·기밀문서 처리 기준 수립

한국어 판례·법령 데이터는 기본 탑재되지 않으니 별도 구축이 필요하다.

## 나에게 미치는 영향

**로펌·기업 법무팀**이라면: 파일럿 테스트용으로 사내 테스트 서버에 올려보라. `docker compose -f docker-compose.prod.yml up -d` 한 줄로 전체 스택(포스트그레스·레디스·캐디 프록시 포함)이 뜬다. `DOMAIN=localhost`로 로컬 테스트도 가능하다. 단, 실무 투입 전엔 **한국어 판례 임베딩 품질**과 **암호화 미적용 구간(벡터·로그)**을 반드시 검증해야 한다.

**일반 직장인·프리랜서**라면: 직접 돌리기엔 진입 장벽이 높다. 대신 '데이터가 내 서버에만 남는다'는 원칙이 필요할 때(계약서 검토, 내부 규정 분석 등) 클라우드형 유료 서비스 대신 검토해볼 대상이 생긴 셈이다. 당장은 챗GPT·클로드에 기밀 문서를 올리지 말고, 케이스사이트 데모나 유사 오픈소스 프로젝트 소식을 지켜보는 편이 현실적이다.

**개발자·기술 담당자**라면: 코드베이스(`frontend/e2e/screenshots.spec.ts` 등)를 열어보면 실제 UI 플로우와 목업 데이터 구조를 바로 확인할 수 있다. 프랙티스 프로필·레드라인·시타토(인용 검증) 등 법률 특화 UX 패턴이 어떻게 구현됐는지 참고하기 좋다. 아파치 2.0이라 포크해 사내 도구로 확장하기도 자유롭다.

## 남은 건 검증이다

제작자가 밝힌 한계도 명확하다. "시타토(인용 검증기) 대체재가 아니다", "변호사 판단 대체 불가", "벡터 청크·채팅 로그는 평문 저장". 한국 도입 시 **개인정보보호법·변호사법·전자문서법** 저촉 여부를 법무팀과 미리 맞춰봐야 한다. 하비 5000억 원 투자의 무게감은 '기능'이 아니라 '책임 감당 능력'에 있다는 점, 케이스사이트를 보며 다시 한 번 느낀다.

본지가 앞서 다룬 [AI가 레고 설계도 그려준다… 오픈소스 'ldraw-nova' 등장](/posts/2026-10-03-ai가-레고-설계도-그려준다-오픈소스-ldraw-nova-등장/) 때도 비슷했다. 도구는 무료로 풀렸지만, '실제 쓰려면 뭐가 더 필요한가'를 따져보니 데이터 정제·하드웨어·도메인 지식이 별도 비용으로 붙었다. 케이스사이트도 같다. **코드는 공짜, 운영은 유료**다.
