오픈AI가 자사 블로그를 통해 프론티어 모델로 반도체 설계를 가속한 구체적 수치를 공개했다. 자체 추론 칩 '할라피뇨'와 AMD 차세대 GPU·CPU 설계에서 PPA(전력·성능·면적) 개선이 실리콘 검증까지 마쳤거나 양산 설계 파일에 반영됐다는 내용이다. 본지가 61일 전 다룬 기사에서는 "검증은 아직"이라고 짚었는데, 이번 발표는 시뮬레이션과 신서시스(합성) 단계 검증을 넘어 실제 테이프아웃(제조 의뢰) 단계까지 진입했다는 점에서 한 걸음 더 나아갔다.

## 할라피뇨·AMD에서 확인된 수치

할라피뇨의 벡터 유닛과 매트릭스 유닛에서 각각 표준 셀 면적 **13%, 10% 감소**를 모델이 제안했고, 이는 실리콘 브링업(초기 구동 검증)에서 입증됐다.

- 벡터 유닛: 부동소수점 가산기·승산기, 변환 로직, 특수 기능 유닛을 파이프라인 단계 재배치로 공유해 중간 저장소 축소
- 매트릭스 유닛: 승산기 하나를 셀 면적 15% 축소하면서 지연을 2클럭에서 1클럭으로 단축

AMD 협업에서는 플래그십 GPU IP 대비 **최대 14% PPA 개선**을 확인했다. "기존 최적화 베이스라인 대비 약 1년 치 진도를 5개월 미만으로 압축했다"는 표현이 블로그에 있다. AMD는 이 중 일부를 이미 최근 테이프아웃한 설계에 반영했고, 나머지는 향후 버전 생산 설계 파일에 넣었다. 차세대 플래그십 CPU 핵심 블록에서도 **한 자릿수 퍼센트 PPA 이득**을 모델 작성 설계로 확인했다고 AMD가 직접 검증했다.

## 모델이 하는 일: RTL 리라이팅과 EDA 도구 검증

핵심은 **시스템버릴로그(SystemVerilog) RTL 코드를 전문가 수준으로 고쳐 쓰는 것**이다. 연산·제어·데이터 이동 회로를 다시 짜고, 시놉시스(Synopsys) EDA 도구로 기능 보존 여부와 PPA 트레이드오프를 자동 평가한다. 오픈AI는 "모델이 마이크로아키텍트 전문가 수준으로 RTL을 추론한다"고 표현했으나, 실제로는 도구 체인(시뮬레이터·신서시스·정형 검증)이 게이트키퍼 구실을 한다. 모델이 제안해도 도구가 거부하면 폐기되는 구조다.

## 커뮤니티는 "헬로월드 칩"이라 의심한다

해커뉴스 댓글 75개 중 다수는 회의적이다. "경쟁사와 차별화된 칩을 내려면 이 정도로 안 된다"는 지적과, "20조(20T) RTL 토큰으로 학습하지 않고서야 진짜 전문가 수준은 불가능하다"는 기술적 반론이 나왔다. "낮은 가지는 이미 땄다"는 평가에 대해선 "AI 적용법 자체를 이제 막 배우는 중"이라는 반박도 있었다. 발표문이 성공 사례만 나열하고 실패율·재시도 비용·엔지니어 개입량은 밝히지 않은 점이 불신을 키운다.

## 검증된 것과 아직 확인 안 된 것

| 항목 | 확인됨 | 미확인 |
|------|--------|--------|
| 할라피뇨 벡터/매트릭스 면적 감소 | 실리콘 브링업 통과 | 전체 칩 수준 PPA 영향 |
| AMD GPU 14% 개선 | 양산 설계 파일 반영 | 어느 블록, 어느 지표 위주인지 |
| AMD CPU 한 자릿수 이득 | AMD 자체 검증 완료 | 차세대 제품 출시 일정 |
| RISC-V 코어 벤치마크 | GPT-4o→최신 모델 점수 상승 | 실제 임베디드 제품 투입 여부 |

시놉시스 도구 통합도 "작업 중" 단계다. 엔지니어가 쓰는 플로우에 모델이 자연스럽게 녹아들려면 라이선스 비용·런타임·오탐(false positive)률 같은 운영 지표가 더 필요하다.

## 쉽게 풀어보면

오픈AI가 만든 AI 모델로 반도체 설계도를 고쳤더니 실제 제조 직전 단계까지 통과했다는 이야기다. 오픈AI 모델은 도면(SystemVerilog RTL)을 고치고, 시놉시스라는 업계 표준 검증 프로그램이 "기능은 그대로인데 면적·전력·속도가 좋아졌다"는 확인서를 끊어줬다.

할라피뇨라는 오픈AI 자체 칩에서는 회로 면적이 10~13% 줄었고, AMD의 차세대 그래픽·중앙처리장치 설계에서도 최대 14% 개선이 나와 이미 제조 의뢰된 설계도에 반영됐다. "보통 1년 걸릴 최적화를 5개월 만에 했다"는 게 오픈AI 주장이다.

하지만 반도체 엔지니어들은 "시범용 간단한 칩(헬로월드)에서는 되는데, 진짜 경쟁력 있는 복잡한 칩에서도 통할지 모른다"고 본다. AI가 수조 개 설계 데이터로 학습하지 않고서야 베테랑 엔지니어의 직관을 흉내 내기 어렵다는 지적도 있다. 오픈AI 발표에는 성공한 케이스만 나와 있고, 몇 번 실패했는지, 엔지니어가 얼마나 손봤는지, 검증 도구 비용은 얼마나 드는지는 빠져 있다.

## 나에게 미치는 영향

일반 사용자가 오늘 당장 체감할 변화는 없다. 하지만 AI 칩 가격 하락 시계가 빨라질 가능성은 열려 있다. 설계 주기가 짧아지면 신제품 출시 간격이 좁아지고, 그게 GPU·NPU 가격 인하로 이어질 수 있다. 오픈AI가 4개월 전 LLM 가격을 80% 내린 배경에도 자체 칩 원가 절감이 깔려 있을 것이다.

개발자라면 코드 생성 AI가 "컴파일러·정적 분석기"와 짝을 이뤄 검증 루프를 도는 패턴을 눈여겨볼 만하다. 칩 설계뿐 아니라 펌웨어·임베디드·하드웨어 가속 라이브러리에서도 같은 워크플로가 퍼질 것이다. 챗GPT나 클로드에서 코드를 짤 때도 "테스트 통과할 때까지 고쳐 줘" 대신 "정적 분석 도구 돌려서 경고 없애 줘"라고 지시해 보라. 검증 도구가 게이트키퍼가 되는 흐름은 소프트웨어 쪽이 더 빠르다.

## 남은 쟁점: 검증 도구가 병목이 된다

시놉시스·케이던스·지멘스 EDA 3사 도구는 라이선스비가 비싸고, 대형 설계 한 번 돌리는 데 며칠이 걸린다. 모델이 초당 수천 개 RTL 변형을 제안해도 도구가 하루에 수십 개만 검증할 수 있으면 병목은 도구 쪽이다. 오픈AI가 "시놉시스와 통합 중"이라고만 밝힌 이유다.

또 하나, 모델이 "전문가 수준"으로 짠 코드를 사람이 읽고 유지보수할 수 있는가다. 블랙박스 최적화로 면적 15%를 아꼈는데 3년 뒤 버그 나면 누가 고치나. 오픈AI 발표에는 가독성·문서화·회귀 테스트 이야기가 없다. 이 부분이 양산 적용의 진짜 걸림돌일 수 있다.

본지가 앞서 다룬 가격 인하 기사와 연결해 보면, 설계 자동화→자체 칩 원가 하락→모델 추론 단가 인하→사용자 요금 인하로 이어지는 고리가 하나 더 단단해졌다. 다만 그 고리의 다음 매듭인 EDA 병목과 유지보수성은 여전히 열려 있다.
