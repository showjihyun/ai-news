## 발견된 취약점의 핵심

파라미터 랩스(Parameter Labs) 연구팀이 챗GPT 공유 기능을 악용해 **타인 계정을 완전히 장악할 수 있는 취약점**을 발견해 보고했다. 공격자는 악성 대화를 만들어 공유 링크를 보내고, 피해자가 링크를 열기만 하면 피해자의 인증된 세션에서 자바스크립트가 실행된다. 피해자는 앱 설치, 코드 붙여넣기, 개발자 도구 열기 등 어떤 추가 행동도 필요 없다. **링크 클릭 한 번이 전부**다.

이 취약점으로 공격자는 피해자의 대화 목록 열람, 비공개 대화 내용 탈취, 챗GPT 인증 API 직접 호출, 외부 서버로 데이터 유출이 가능했다. 오픈AI는 10월 26일 패치를 완료하고 **최고 등급인 P1**로 분류했다.

## 공격 연쇄: 두 기능의 우연한 결합

공격의 시작은 서로 관련 없어 보이는 두 기능이었다. **대화형 그래프**와 **HTML 미리보기(Preview)**다.

챗GPT는 HTML 코드 블록을 작동하는 웹페이지로 바꿔주는 미리보기 기능을 제공한다. 이 페이지는 임의 코드를 포함할 수 있어, 브라우저는 이를 **다른 주소의 제한된 프레임(iframe)**에서 실행한다. 원칙적으로 이 프레임은 메인 챗GPT 페이지(`parent.document`)를 읽을 수 없다.

문제는 그래프 기능이었다. 그래프 뒤편에서는 **매스라이브(MathLive)**라는 수학 라이브러리가 로드되는데, 이 라이브러리는 화상 키보드 관련 메시지를 수신하는 리스너를 **메인 챗GPT 페이지에 설치**한다. 브라우저의 `postMessage` API를 쓰는 정상적인 통로다.

## 샌드박스를 뚫은 열쇠: 출처 미확인

매스라이브의 리스너는 **메시지 보낸 이의 출처를 검증하지 않았다**. `origin: none` 정책으로, 어떤 주소에서 온 메시지든 받아들였다. 미리보기 프레임은 신뢰할 수 없는 발신자고, 그래프가 설치한 리스너는 신뢰할 수 없는 수신자였다. **서로 무관한 두 기능이 우연히 샌드박스를 건너는 다리를 만든 셈**이다.

공격자는 미리보기 프레임에서 두 메시지를 보냈다. 첫째, 가상 키보드 레이아웃을 공격자 HTML로 교체. 둘째, 키보드 표시 명령. 키보드가 열리면 매스라이브는 전달받은 레이아웃을 HTML 문자열로 합쳐 메인 페이지의 `innerHTML`에 넣는다. 새니타이징(살균) 함수로 보였던 `createHTML`은 실제로는 입력을 **신뢰됨으로 표시하고 그대로 통과**시켰다.

## 스크립트 실행까지: 유튜브 도메인의 구멍

`innerHTML`로 넣은 `<script>` 태그는 자동 실행되지 않는다. 공격자는 `srcdoc` 속성을 쓰는 **iframe을 주입**해 이 한계를 넘었다. 매스라이브는 이 프레임을 메인 문서에 **샌드박스 속성 없이** 삽입했다.

오픈AI의 콘텐츠 보안 정책(CSP)은 인라인 스크립트를 차단하고 몇몇 도메인에서만 스크립트 로드를 허용했는데, **허용 목록에 유튜브가 있었다**. 유튜브의 oEmbed 엔드포인트를 이용해 자바스크립트를 반사시켜 실행하는 방식으로 우회했다. 자바스크립트 실행권을 얻은 뒤로는 인증된 API 호출로 비공개 데이터를 가져와 이미지 레퍼런스 등으로 유출하는 건 **사소한 일이었다**.

## 오픈AI의 대응과 버그 바운티

오픈AI는 10월 26일 취약점을 차단했다. 파라미터 랩스에는 **5,000달러 버그 바운티**를 지급했다. 사이먼 윌리슨(Simon Willison)은 "이 정도 심각성이면 바운티가 너무 싸다"고 평했다. 윌리슨은 이번 사안이 **아티팩트 패턴(구 캔버스, 현 HTML 미리보기) 구현의 본질적 위험**을 보여준다고 지적했다. 샌드박스된 iframe에서 실행되는 비신뢰 코드가 부모 페이지와 통신할 수 있는 경로가 존재하면, 사소한 구현 실수 하나가 연쇄 해킹으로 이어진다는 것이다.

## 쉽게 풀어보면

파라미터 랩스가 발견한 건 **챗GPT 공유 링크 하나로 남의 계정을 훔칠 수 있는 구멍**이다.  
상황을 비유하면 이렇다. 당신이 친구에게 "이 대화 봐봐" 하며 링크를 보냈다. 친구가 링크를 여는 순간, 친구의 챗GPT 화면 안에서 **당신이 심어둔 프로그램이 친구 권한으로 작동**하기 시작한다. 친구의 비공개 대화 기록을 읽고, 파일을 내려받고, 친구 이름으로 챗GPT에 명령을 내릴 수 있다. 친구는 그저 링크를 눌렀을 뿐이다.

기술적으로는 두 개의 **각자로는 안전해 보이던 기능**이 만나 벌어진 일이다.  
첫째, 챗GPT가 수식을 그릴 때 쓰는 **매스라이브**라는 도구는 메인 화면에 "키보드 설정 바꿔줘"라는 메시지 받는 창구를 열어뒀다.  
둘째, 챗GPT의 **HTML 미리보기** 기능은 격리된 틀 안에서 돌아가지만, 그 틈새로 메시지를 보낼 수는 있었다.  

미리보기 쪽에서 "키보드 레이아웃을 내 맘대로 바꿔"라는 메시지를 던졌고, 메인 화면의 매스라이브는 **보낸 이가 누구인지 확인도 안 하고** 그 말을 들었다. 바꿔치기된 레이아웃엔 악성 HTML이 들어 있었고, 이게 메인 화면에 심어졌다. 거기서 한 단계 더 나아가 **샌드박스 없는 iframe**을 심고, CSP(콘텐츠 보안 정책)가 허용하던 **유튜브 도메인**을 경유해 자바스크립트를 실행시켰다.  

이게 왜 중요하냐면, **공유 링크는 누구나 만들 수 있고 누구나 보낼 수 있다**는 점이다. 피싱 메일처럼 위장할 필요도 없다. 정상적인 챗GPT 공유 링크 그대로다.

## 나에게 미치는 영향

이 취약점은 **이미 패치됐다**. 10월 26일 이후 공유 링크를 열었다면 안전하다. 하지만 **패치 전 링크를 열어둔 탭이 남아 있다면** 여전히 위험할 수 있다.

당장 할 수 있는 확인 사항 세 가지:

- **열려 있는 챗GPT 탭을 모두 닫고 다시 로그인**하세요. 세션 쿠키가 갱신됩니다.
- **최근 공유 링크를 클릭한 기록이 있다면** 그 대화 내용을 점검하세요. 낯선 기기 로그인 알림이 떴는지도 확인하세요.
- **의심스러운 공유 링크는 열지 마세요**. 발신자를 안다 해도 그 계정이 해킹됐을 수 있습니다.

개발자나 보안 담당자라면: **iframe 샌드박스 속성(`sandbox`)**과 **`postMessage` 수신 측의 출처 검증(`event.origin`)**이 빠짐없이 적용됐는지 자체 점검하세요. 이번 사고는 "격리됐다"는 가정 하나만 믿고 출처 검증을 생략한 전형적 사례다.

## 남은 쟁점: 바운티 금액과 공개 시점

파라미터 랩스는 발견 시점을 **10월**로만 밝혔다. 정확한 신고일과 패치까지 걸린 시간은 공개되지 않았다. 오픈AI가 P1로 분류했음에도 **5,000달러**만 지급한 배경도 불투명하다. 유사 취약점이 다른 AI 서비스(클로드, 제미나이 등)의 아티팩트/캔버스 기능에도 존재할 수 있다는 게 보안 커뮤니티의 공통된 우려다. 본지는 오픈AI 측에 바운티 산정 근거와 타 서비스 영향 여부를 질의했으며, 답변이 오는 대로 후속 보도하겠다.
