## 커서 마켓플레이스서 검증 계정으로 악성 확장 유포

케빈 보몬트 보안 연구자에 따르면 **앤트로픽의 공식 인증 계정으로 커서 마켓플레이스에 올라온 클로드 코드 VS코드 확장 2.1.313 버전**에 원격 접근 트로이목마가 포함돼 있었다[^1]. 이 확장은 설치 즉시 개발자 랩톱에서 호스트명, 사용자명, OS, 공개 IP, 깃허브 이메일 등 정보를 수집하고 공격자가 제어하는 SSH 공개키를 `~/.ssh/authorized_keys`에 추가했다.

이어 로컬 SSH 서비스를 활성화하고 리버스 SSH 터널을 열어 **지속적인 원격 접속 경로**를 만들려 했다. macOS는 `LaunchAgent`, 윈도는 예약 작업으로 60초마다 터널 재시도를 시도했다. 수집한 정보는 포트 8099의 `/beacon` 엔드포인트로 전송됐다.

[^1]: Kevin Beaumont, "Anthropic hacked via Cursor to deliver remote access trojan", DoublePulsar, 2026년 10월

## 악성 코드는 확장 로드 즉시 실행…사용자 조작 불필요

포라이언 분석에 따르면 **악성 페이로드는 `extension.js` 파일의 최상단에 IIFE(즉시 실행 함수) 형태로 주입**돼 있었다[^2]. 확장 통상 활성화 콜백이 실행되기 전, 노드가 파일을 로드하는 순간 자동 실행된다. 사용자가 확장을 클릭하거나 기능을 쓰지 않아도 감염된다.

코드는 `child_process`, `fs`, `os`, `path`, `http`, `crypto` 표준 모듈만 써서 외부 의존성 없이 동작한다. SSH 키 주석은 `svc-telemetry`로 위장했으며, 키 지문으로만 탐지 가능하다.

[^2]: Phorion, "Backdoor in official Claude Code for VS Code extension on Cursor Marketplace", phorion.io, 2026년 10월

## 맥·윈도 구현 버그로 실제 침투는 제한적이었다

맥에서는 `systemsetup -getremotelogin` 명령이 관리자 권한 없이 실행되면 에러를 내며 종료 코드 0을 반환한다. 악성 코드는 출력이 `Off`일 때만 SSH 활성화를 시도하는데 **에러 메시지가 `Off`를 포함하지 않아 활성화 단계를 건너뛴다**. 키와 지속성만 남고 인바운드 접속은 차단된다.

윈도 파워셸 명령은 `/bin/sh` 하드코딩된 헬퍼 함수로 전달돼 **일반 윈도 환경에서 아예 작동하지 않는다**. 리눅스는 `systemctl` 경로로 시도되나 권한 상승 익스플로잇은 없다. 표준 사용자 컨텍스트에서 `sudo -n`이 실패하면 서비스 시작도 막힌다.

## 커서 "최대 5천 명 영향"…앤트로픽 "우린 무관, 커서 책임"

커서 블로그에 따르면 **악성 버전 설치 사용자는 약 5천 명**으로 추산된다[^3]. 커서는 "악성 버전은 앤트로픽이 개발하지 않았다"고 밝혔으나, 보몬트는 "앤트로픽 인증 계정으로 업로드됐으므로 '개발 안 했다'는 표현은 책임 회피"라고 지적했다.

앤트로픽 측 펠릭스는 해커뉴스 댓글에서 **공식 VS코드 마켓플레이스 버전은 영향 없다**고 확인했다[^4]. 오픈VSX, 비주얼 스튜디오 마켓플레이스, 커서 모두에서 2.1.313 버전은 삭제됐다. 앤트로픽은 8시간 뒤 2.1.314를 배포해 백도어 코드를 제거했으나 **이미 감염된 시스템의 SSH 키와 지속성은 자동 삭제하지 않는다**.

[^3]: Cursor blog via Reuters, "Cursor says up to 5,000 users affected by tampered Claude Code extension", 2026년 10월
[^4]: Felix (Anthropic), Hacker News comment #50304129, 2026년 10월

## 바이낸스 등 주요 기업 개발 환경도 노출됐다

보몬트는 **"바이낸스를 포함한 수천 곳 고객사가 클로드 코드와 커서를 랩톱에서 운용 중"**이라고 전했다. 개발자 머신은 소스코드, 인프라 크리덴셜, 내부 네트워크 접근 권한을 가진 고가치 표적이다. 공급망 공격으로 IDE 확장이 해킹되면 빌드 파이프라인, 클라우드 자격증명, 프로덕션 배포 키까지 연쇄 유출될 수 있다.

이번 사고는 **확장 마켓플레이스의 인증 계정 탈취만으로 코드 리뷰·CI·서명 검증 전체를 우회**했음을 보여준다. 커뮤니티에서는 "배포 단계 2FA가 필요하다", "패키지 관리자에 배포 전 검증 훅을 둬야 한다"는 의견이 나왔다[^5].

[^5]: Hacker News comments on item #50300683, 2026년 10월

## 쉽게 풀어보면

**커서라는 AI 코드 편집기의 확장 마켓플레이스에서, 앤트로픽 공식 인증 마크가 붙은 '클로드 코드' 확장의 특정 버전(2.1.313)에 도둑 프로그램이 숨겨져 있었습니다.** 이 확장 설치만 하면 사용자가 아무 버튼도 누르지 않았는데도 백그라운드에서 몰래 실행됩니다.

도둑 프로그램은 내 컴퓨터 이름, 계정, 아이피, 깃허브 이메일 등을 훔쳐 가고, **나만의 비밀 열쇠(SSH 키)를 내 컴퓨터에 심어 둡니다.** 나중에 도둑이 이 열쇠로 내 컴퓨터에 원격 접속해 파일과 코드를 마음껏 볼 수 있게 하려는 의도였습니다.

다행히 맥과 윈도에서는 프로그래밍 실수(버그) 때문에 **실제로 원격 접속이 열리지는 않았습니다.** 하지만 열쇠와 '다시 접속 시도하는 예약 작업'은 이미 심어져 있습니다. 커서 측은 최대 5천 명 개발자가 이 버전을 설치했다고 밝혔습니다. 앤트로픽은 "우리가 만든 게 아니고 커서 쪽 문제"라며 책임을 넘겼고, 8시간 뒤 수정된 버전(2.1.314)을 냈습니다. **이미 당한 컴퓨터는 자동으로 고쳐지지 않습니다.**

## 나에게 미치는 영향

**한국 개발자도 커서를 쓰거나 클로드 코드 확장을 VS코드·커서에서 설치했다면 대상이 될 수 있습니다.** 커서 마켓플레이스에서 확장을 받은 적이 있다면 지금 바로 확인하세요.

**확인 방법**: 터미널에서 `code --list-extensions --show-versions`(VS코드) 또는 커서 확장 관리자에서 `claude-code` 버전이 `2.1.313`인지 보세요. 맞다면 즉시 `2.1.314` 이상으로 업데이트하세요.

**이미 2.1.313을 설치했던 컴퓨터라면** 다음을 직접 점검해야 합니다.

1. `~/.ssh/authorized_keys` 파일을 열고 `svc-telemetry` 주석이 있는 줄이 있는지 확인 → 있으면 그 줄 삭제
2. `~/.ssh` 폴더 권한 `0700`, `authorized_keys` 권한 `0600` 유지
3. 맥: `launchctl list`로 `svc-telemetry` 같은 낯선 에이전트 있는지 확인 → 있으면 `launchctl remove`로 삭제
4. 윈도: 작업 스케줄러에서 낯선 시작 작업(특히 `svc-telemetry` 관련) 찾아 사용 안 함 처리
5. 리눅스: `systemctl --user list-timers`, `crontab -l`로 의심스러운 항목 점검

**기업 보안팀이라면** 엔드포인트 탐지·대응(EDR) 룰로 `authorized_keys` 변경, `systemsetup -setremotelogin on`, `schtasks /create` 등 행위를 모니터링하세요. 마이크로소프트 디펜더용 KQL 쿼리는 보몬트 마스토돈(@gossithedog@cyberplace.social)에서 공유 중입니다.

**당장 오늘 할 일**: 커서·VS코드 확장 목록 확인 → 2.1.313이면 업데이트 → `authorized_keys` 점검 → 이상 있으면 보안팀·관리자에게 신고. 개발자 랩톱 하나가 뚫리면 회사 전체 인프라가 위험해집니다.

## 남은 쟁점과 대응 방향

앤트로픽은 공식 성명을 내놓지 않았고 고객에게 개별 알림도 하지 않았다. **공식 채널로 배포된 확장조차 마켓플레이스 계정 탈취 시 공급망 전체가 무너진다는 사실**이 확인됐다. 커서·VS코드·오픈VSX 등 주요 마켓플레이스는 배포 서명 검증·2FA·배포 전 승인 훅 같은 2차 방어층을 갖춰야 한다.

한국 기업 중 커서·클로드 코드를 쓰는 곳이라면 **이번 기회에 개발 환경 격리·최소 권한·확장 설치 승인 프로세스**를 재점검해야 한다. 본지가 앞서 다룬 [오픈AI "미국이 AI 국제표준 주도해야"…韓 기업 '이중 인증' 부담 커진다](/posts/2026-09-22-오픈ai-미국이-ai-국제표준-주도해야韓-기업-이중-인증-부담-커진다/) 기사에서도 공급망 보안 요구가 강화되는 흐름이 언급된 바 있다.

감염 여부 확인과 키 제거는 **개발자 각자가 지금 당장 해야 할 행동**이다. 패치 버전 설치만으로는 끝나지 않는다.
