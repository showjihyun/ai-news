## 쉽게 풀어보면

해커뉴스 사용자가 클로드 3.5 소넷에게 **"회전하는 우주정거장(오닐 실린더) 시뮬레이션을 브라우저에서 돌려줘"**라고 요청했습니다. 클로드는 웹GL(브라우저가 그래픽카드 성능을 빌려 3D를 그리는 기술) 코드를 한 번에 작성해 줬습니다.

마우스로 실린더를 돌리고 **'fly(내부 날아다니기) 버튼'**을 누르면 관통 비행을 체험합니다. 고성능 데스크톱에선 부드럽게 돌아갑니다.

하지만 **내장 그래픽**만 단 일반 노트북에선 'fly' 버튼을 누르는 순간 탭이 하얗게 변하며 죽습니다. 뷔페에 음식이 잔뜩 차려져 있는데, 내 접시가 너무 무거워서 들 수 없는 꼴입니다. 브라우저가 감당할 GPU 연산량을 넘어섰기 때문입니다.

만든 사람은 "잘 돌아간다"지만, 쓰는 사람 다수는 "못 쓴다"는 게 현실입니다.

## 해커뉴스 반응: "절반은 못 돌린다"

해커뉴스에 글이 떴습니다. 점수 21, 댓글 18개. 댓글 절반 가까이가 크래시와 렉을 보고합니다.

"fly 버튼 누르자마자 탭이 죽었다"는 증언이 여럿입니다. "절반 이상이 제대로 못 돌린다"는 지적도 나옵니다. "이건 웹사이트지 오닐 실린더가 아니다, 걸어다닐 수도 없다"는 냉소도 보입니다.

15년 전 에릭 브루네의 '라마와의 랑데부' 영상을 보고 비슷한 게임을 구상했다는 개발자도 나타났습니다. 손코딩으론 엄두 못 냈던 걸 AI로 단숨에 뽑아냈다는 뜻입니다.

작성자가 워크스루 영상 요청에 답했는지, 최소 사양을 문서화했는지는 본지가 확인하지 못했습니다.

## 한국 직장인 노트북, 이걸 돌릴 수 있을까

국내 직장인 대다수가 쓰는 업무용 노트북은 인텔 UHD, 아이리스 Xe, AMD 라데온 베가 같은 **내장 그래픽**입니다. 별도 GPU 없는 이 환경에서 수만 폴리곤·실시간 물리 연산을 브라우저 탭 하나가 감당할 수 있을지는 미지수입니다.

회사 노트북으로 접속해 'fly' 버튼을 눌러보는 것 자체가 스트레스 테스트가 됩니다.

보안 정책으로 **하드웨어 가속이 강제 꺼진 단말**도 적지 않습니다. 크롬 `about:gpu`에서 '하드웨어 가속' 항목이 'Disabled'로 뜨면, 설정에서 켜도 재부팅 후 관리자 권한으로 다시 꺼지는 경우가 많습니다. 이 상태론 웹GL 데모 대부분이 흰 화면으로 끝납니다.

본지가 앞서 다룬 **'AI 코딩 툴 실사용기 3회차'**에서도 똑같이 나타났습니다. 만드는 속도가 빨라진 만큼, 부수는 검증에 더 공을 들여야 합니다. 이 대목이 걸립니다.

## 아이디어 15년, 구현 15분, 검증은 아직

아이디어 구현 속도와 실행 안정성 사이에 간극이 있습니다.

작성자가 워크스루 영상을 올리거나 최소 사양을 문서화하거나 폴백(저사양 모드)을 넣기 전까진 이 프로젝트는 **"데모용으로만 볼 수 있는 것"**으로 남습니다.

AI가 복잡한 3D 수학·물리 코드를 한 번에 짜줄 가능성을 보여준 건 분명합니다. 동시에 브라우저라는 불확실한 런타임 위에 올렸을 때 생기는 호환성 문제도 적나라하게 드러냈습니다.

## 5분 만에 해보는 하드웨어 가속 점검

오늘 바로 확인해 볼 수 있는 구체적 단계입니다.

크롬 주소창에 `about:gpu`를 입력하세요. **Graphics Feature Status** 항목 중 'WebGL'·'Hardware acceleration'이 **'Hardware accelerated'**로 떠야 정상입니다.

'Disabled' 또는 'Software only'면 설정 → 시스템 → **'가능한 경우 하드웨어 가속 사용' 켜기** → 크롬 재시작 순으로 시도하세요.

그래도 'Disabled'면 **회사 IT 관리자 문의**가 필요합니다. 그룹 정책으로 강제 고정된 경우 사용자 권한으론 못 풉니다.

하드웨어 가속이 켜진 상태에서 데모 접속 → **F12 → Performance 탭** → 녹화 버튼 클릭 → 'fly' 버튼 누르기 → GPU 메모리 그래프 급증 시 내 기기에서 무리입니다.

흔히 막히는 지점: 설정에서 켰는데 재부팅 후 다시 꺼짐 → **관리자 권한 필요**. 크롬 단축아이콘 우클릭 → 속성 → 대상 끝에 `--disable-gpu` 붙어 있음 → **삭제 후 재시작**.

## 나에게 미치는 영향

클로드에게 **"웹GL로 물리 시뮬레이션 프로토타입 짜줘"**라고 프롬프트를 던지면 초기 코드가 나옵니다. 단, 배포 전 최소 사양 테스트는 직접 해야 합니다.

크롬·파이어폭스·사파리, 내장/외장 GPU, 모바일/데스크톱, 회사 보안정책 적용 단말에서 돌려봐야 합니다.

**지금 바로 할 수 있는 것 하나:** 클로드에게 코드 짜게 하고, 직접 빌드·테스트·배포까지 해보는 사이클을 돌려보세요. 그게 지금 일반인이 AI로 만들 수 있는 **가장 확실한 학습 루프**입니다.

## 남은 건 검증이다

만드는 속도가 빨라진 만큼, 부수는 검증에 더 공을 들여야 합니다. 그게 지금 AI 코딩의 진짜 과제입니다.

작성자가 최소 사양을 문서화하거나 폴백을 넣기 전까진 이 프로젝트는 데모로 남습니다.
