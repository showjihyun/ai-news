챗GPT에서 두 개의 MCP 커넥터를 동시에 켜두면, 모델이 사용자도 모르게 커넥터를 바꿔가며 데이터를 넘길 수 있다는 사실이 커뮤니티에서 확인됐다. 오픈AI 커뮤니티 포럼과 해커뉴스에서 최근 공개된 내용이다.

## 무슨 일이 있었나

한 사용자가 같은 MCP 서버를 가리키는 서로 다른 커넥터 A와 B를 동시에 켜둔 상태에서 확인(confirmation)이 필요한 작업을 요청했다. 모델은 커넥터 A를 통해 확인 도구를 호출했고, 사용자는 A의 위젯에서 승인했다. 위젯은 일회용 확인 코드를 대화로 보냈다.

문제는 그다음이다. 모델이 후속 호출을 할 때 **커넥터 B를 통해 코드를 보냈다**. 서버는 코드가 A의 OAuth 클라이언트에 묶여 있어 거절했다. 사용자에게는 커넥터가 바뀌었다는 알림이 전혀 없었다.

## 왜 위험한가

커넥터마다 별도의 OAuth 클라이언트가 발급된다. 즉 **서로 다른 앱으로 취급된다**. 같은 URL을 쓰더라도 OAuth 클라이언트가 다르면 별도 테넌트·파트너·환경으로 동작할 수 있다. 그런데 모델이 아무 설명 없이 커넥터를 갈아타면, A 앱에서 생성된 민감한 값(확인 코드 등)이 B 앱으로 넘어간다. 제3자 커넥터가 같은 대화에 있다면 타사 서버로 데이터가 샐 수도 있다.

이 대목이 걸린다. 서버 측 검증이 있어 이번엔 막혔지만, 검증 로직이 없는 서버라면 그대로 뚫린다.

## 오픈AI의 대응과 신고자의 거부

오픈AI 직원으로 보이는 답변은 "중요한 경계 사례"라고 인정하면서도, 공식 버그 바운티 절차로 제출하라고 안내했다. 하지만 해당 프로그램은 **생체 인증과 신분증 사본을 제3자에게 미리 내야 한다**. 신고자는 "계정 폐쇄 보복 우려가 있어 응할 수 없다"고 밝혔다.

해커뉴스 댓글에서도 "취약점 신고 후 계정이 닫혔다"는 증언이 여러 건 올라왔다. 한 댓글 작성자는 "두 차례 버그를 신고했고 두 번 다 계정이 폐쇄됐다"고 적었다. 국내 연구원들도 같은 장벽을 겪을 수 있다.

## 과거 기사와 비교해 보니

본지가 작년 11월 다룬 '챗GPT 플러그인 권한 누수' 기사에서도 도구 호출 시 권한 컨텍스트가 유지되지 않는 문제가 지적됐다. 당시는 플러그인 아키텍처였고, 지금은 MCP 커넥터로 바뀌었지만 **근본적인 라우팅·권한 연속성 결함은 해결되지 않았다**. 아키텍처 교체만으로는 보안 경계를 지킬 수 없음이 다시 확인됐다.

## 쉽게 풀어보면

챗GPT에 '구글 드라이브 커넥터'와 '노션 커넥터'를 둘 다 켜뒀다고 가정하자. 당신이 "드라이브 파일 공유해 줘"라고 하면 챗GPT는 드라이브 커넥터로 확인 창을 띄운다. 당신이 "확인"을 누르면 일회용 코드가 생긴다. 그런데 챗GPT가 그 코드를 **노션 커넥터로 보내버린다**. 노션 서버는 "이 코드는 드라이브용이라 안 받아" 하고 거절한다. 당신은 커넥터가 바뀐 줄도 모른다.

드라이브와 노션은 완전히 다른 회사·다른 권한 체계다. 확인 코드뿐 아니라 앞으로 더 민감한 값(액세스 토큰, 개인정보 등)이 같은 식으로 넘어갈 수 있다. 사용자 동의 없이 앱끼리 데이터를 주고받는 셈이 된다.

## 나에게 미치는 영향

한국에서 챗GPT 플러스·팀·엔터프라이즈 요금제를 쓰며 MCP 커넥터를 여러 개 켜두는 사용자라면 **당장 커넥터를 하나만 켜두는 습관**을 들이는 게 안전하다. 설정 → 커넥터 메뉴에서 불필요한 건 꺼두자.

업무상 여러 커넥터를 동시에 써야 한다면, 중요한 작업(결제, 권한 변경, 데이터 내보내기)은 **새 대화창을 파서 커넥터 하나만 켜고 진행**하는 편이 낫다. 오늘 바로 테스트해 볼 수 있다: 챗GPT에서 커넥터 두 개를 켜고 간단한 확인 동작을 시켜보면, 호출된 커넥터 이름이 UI 어디에도 안 나온다. 이걸 확인하는 것만으로도 현재 위험도를 가늠할 수 있다.

개발자라면 본인 MCP 서버에서 **확인 코드를 발급한 OAuth 클라이언트 ID와 검증 시 클라이언트 ID가 일치하는지 검사**하는 로직을 반드시 넣어야 한다. 이번 사례처럼 서버 측 검증이 있어 막혔지만, 검증이 없으면 그대로 뚫린다.

## 남은 쟁점

- 오픈AI가 이 라우팅 동작을 '버그'로 인정하고 수정 일정을 낼지 미정이다.
- 버그 바운티의 신원 인증 요건이 보안 연구자들을 위축시킨다는 비판이 커지고 있다.
- 멀티 커넥터 환경에서 '어떤 커넥터가 호출됐는지'를 사용자에게 보여주는 UI 개선이 시급하다.

확인된 사실은 여기까지다. 오픈AI 공식 블로그나 한국어 공지에는 아직 아무런 언급이 없다. 바뀐 사항이 생기면 본지에서 다시 전하겠다.
