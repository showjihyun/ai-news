## 자동 승인이 부른 사고

앤스로픽이 제공하는 **클로드 코드(Claude Code)**의 '다시 묻지 않기(Don't Ask Again)' 설정이 공개 깃허브 저장소에 비밀번호와 API 키를 노출시켰습니다. 보안 업체 아피이로(Apiiro) 조사에 따르면 공개 저장소 1,122개 파일에서 실제 비밀 정보가 발견됐습니다. 이 중 539개 저장소는 클로드 코드가 공동 작성자(co-authored)로 표시된 커밋으로 파일이 변경된 이력이 있습니다.

자료: 아피이로 블로그, 해커뉴스 토론

## 왜 위험한가

'다시 묻지 않기'는 사용자가 특정 명령어를 승인하면 이후 같은 패턴의 명령을 **자동 실행**하는 편의 기능입니다. `Bash(python:*)`나 `Bash(node:*)` 같은 인터프리터 규칙을 한 번 허용하면, 이후 파이썬이나 노드 명령은 묻지 않고 수행됩니다. 아피이로는 조사 대상 저장소 43%가 이런 규칙을 쓰고 있었고, 5%는 모든 셸 명령어를 아예 열어뒀다고 밝혔습니다.

문제는 모델이 비밀 파일을 읽고, 그걸 커밋에 포함시켜 버리는 상황을 사용자가 인지하지 못한다는 점입니다. 해커뉴스 댓글에서도 **"인간이 승인 피로로 실수한다"**는 지적이 나왔습니다.

자료: 아피이로 블로그, 해커뉴스 댓글

## 커뮤니티는 어떻게 보는가

해커뉴스 토론(점수 48, 댓글 39)은 두 갈래로 나뉩니다.

- **사용자 책임론**: "비밀번호 든 파일을 공개 저장소에 올린 사용자 잘못"이라는 의견
- **도구 설계 비판**: "자동 승인 기본값이 너무 공격적", "정적 분석으로 위험 명령을 걸러야 한다"는 반론

앤스로픽 측은 "권한 시스템을 다층으로 구성했고 정적 분석으로 위험 명령을 감시 중"이라고 답변했지만, 구체적 차단 규칙이나 한국어 안내 문서는 아직 공개되지 않았습니다.

자료: 해커뉴스 댓글, 앤스로픽 대응 언급

## 한국 개발자가 확인해야 할 것

클로드 코드를 쓰는 국내 개발자라면 지금 바로 세 가지를 점검하세요.

1. **설정 파일 열기**: `~/.claude-code/settings.json`에서 `permissions` 항목 확인
2. **자동 승인 규칙 삭제**: `"bash": "*"` 또는 `"python": "*"` 같은 와일드카드 규칙이 있다면 제거
3. **깃허브 이력 검색**: 본인 저장소에서 `co-authored-by: Claude` 커밋이 있는지 `git log --grep="Claude"`로 조회

한국어 공식 문서에는 이 설정 변경법이 아직 없습니다. 앤스로픽 디스코드나 깃허브 이슈에서 한국 사용자 질문이 올라오고 있으니 참고하세요.

## 쉽게 풀어보면

클로드 코드는 개발자가 터미널에서 자연어로 명령하면 코드를 짜주고 실행까지 해주는 도구입니다. **'다시 묻지 않기'는 "이 명령 패턴은 앞으로 그냥 실행해도 돼"라고 한 번 허락하면, 다음부터는 확인 창 없이 바로 돌리는 기능**입니다.

뷔페에서 한 번 "이 접시는 마음껏 담으세요" 허락받으면, 이후 매번 직원에게 묻지 않고 접시를 채우는 꼴입니다. 편하지만, **직원이 실수로 쓰레기통까지 접시에 담아 테이블로 갖다 놓을 수 있습니다**. 그게 이번에 깃허브 공개 저장소에 비밀번호가 올라간 경위입니다.

모델이 `.env` 파일이나 `config.json` 같은 비밀 설정 파일을 읽고, 그걸 깃 커밋에 포함시켜 푸시해버린 겁니다. 사용자는 "파이썬 실행만 허용했는데 왜 비밀 파일이 커밋됐지?"라고 뒤늦게 알게 됩니다.

## 나에게 미치는 영향

클로드 코드 무료 티어를 쓰는 일반 사용자도 **자동 승인 규칙이 켜져 있다면 같은 위험에 노출**됩니다. 지금 바로 터미널에서 `claude config get permissions`를 쳐서 설정값을 보세요. `bash`나 `python` 앞에 `*`이 붙어 있다면 즉시 지우세요.

이미 공개 저장소에 비밀 정보가 올라갔다면 **깃허브 설정 → Secrets and variables → Actions에서 해당 키를 폐기하고 새로 발급**해야 합니다. 키가 노출된 커밋만 지워선 안 됩니다. 깃허브 이력엔 그대로 남으니까요.

챗GPT나 제미나이 CLI를 쓰는 분도 남 일 아닙니다. **어떤 AI 코딩 도구든 '자동 실행' 권한을 줬다면 비밀 파일 접근을 막는 규칙을 별도로 걸어둬야 합니다.**

## 남은 질문

아피이로 조사만으로는 **국내 기업 저장소 피해 규모**를 알 수 없습니다. 비공개 저장소는 조사 대상이 아니었기 때문입니다. 앤스로픽이 한국어 보안 가이드를 낼지, 자동 승인 기본값을 바꿀지도 미정입니다.
